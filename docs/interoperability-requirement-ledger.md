# Archive Interoperability Requirement Ledger

**Format:** 6
**Reviewed:** 2026-10-29
**Scope:** archive-format-plan.md Phases 0–3 and the basic Interchange Profile 1 acceptance in Phase 5.

This ledger maps each scoped requirement area to every frontend/build in
[the interoperability matrix](interoperability-matrix.md), including the
Classic Mac copied-source kit, the Windows DLL-backed GUI, and the Total
Commander WCX consumer. Status is evidence-based: a cross-build is not a target
runtime test, and implementation described in the matrix is not by itself a
passing fixture. The project does not require backward compatibility; readers
intentionally reject formats 1–5.

Status codes describe the strongest evidence for the *whole acceptance area* on
that row: **H** = host fixture passed; **E** = emulator/guest filesystem fixture
passed; **X** = cross-build or syntax check only; **P** = partial evidence with
known behavior or coverage gaps; **U** = unqualified or blocked. A code is not a
claim that every subcase in the area passed. The final column identifies the
fixture/environment and the remaining behavior or target evidence. `—` means
the shared core/test applies, but no separate frontend-specific execution is
claimed. See the linked matrix row for detailed implementation behavior and
existing results. Native Haiku/BeOS qualification is explicitly deferred by user decision
(2026-10-30) because no verifiable target environment is available; its partial
status remains recorded but does not block the current completion gate. Reopen
that target row when the toolchain/runtime and BFS test volume are available.

## Ledger result

The shared format-6 contract and profile have host-level evidence, and Atari,
Amiga, DOS16, and Linux mini have meaningful emulator/guest-filesystem evidence.
That does not close the frontend cross-product: GUI flows, Windows and .NET/DLL
runtime behavior, most native POSIX targets, OS/2, Win16, CP/M-86, QDOS,
Human68k, RISC OS, Plan 9 native APIs and Classic Mac runtime remain unqualified to the extent
shown above. Haiku/BeOS native qualification is unqualified but explicitly
deferred and excluded from the current completion gate by user decision. Known partial mappings (for example
unsupported directory attributes) are results, not silent passes. This ledger
is the I01 inventory; I02–I07 still own fixes, reproducible corpus expansion,
target qualification, resource accounting, and the final release gate.
