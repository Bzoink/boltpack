## Core evidence

- Full and mini cores emit and accept format 6 only.
- Both cores validate counted UTF-8 names, canonical relative path components,
  primary-name uniqueness, inline/table agreement, and supplementary-group
  framing before extraction or archive editing.
- Portable metadata envelopes are bounded to 256 bytes. Duplicate or orphaned
  portable records and duplicate resource forks are rejected.
- Archive-edit tests copy and append a complete group containing a primary
  file, resource fork, native metadata, and portable FAT metadata, then verify
  integrity and that deletion removes the entire group while preserving the
  primary's timestamp and mode flags.
- The mini writer and reader enforce the serialized-size limit, including file
  table and footer overhead. Host tests exercise write overflow, finalization
  overhead, and oversized header rejection.
- Three fixed format-6 archives are laid out from the normative format and
  codec descriptions without calling either archive writer: a 170-byte
  blocked Stored entry, a 158-byte unframed Stored entry, and a 159-byte
  unframed BoltLite entry. Both cores integrity-test the layouts and extract
  both single-blob cases. Checks cover matching inline/table fields, unknown
  timestamps, fixed payload/table/header CRC-32 values, corrupt payload
  detection, and mini rejection of an oversized single blob before opening
  output.
- The full writer API and Linux, Windows, DOS, Atari, OS/2, macOS, QL, Plan 9,
  RISC OS, and X68000 CLIs can opt into Interchange Profile 1. Linux and
  Windows FLTK GUIs offer it for creation/network sending; Atari GEM, Amiga
  GadTools, native Win32, Windows .NET, macOS Cocoa, Haiku BeAPI, and the
  Retro68 Classic Mac 68k source and PowerPC GUIs offer it for creation. The full writer
  checks method, block size, entry size/count, projected table and footer
  size, and existing archive conformance before profile append. Mini readers
  verify profile archives emitted by full-writer paths.
- `make win32-exe win64-exe` cross-builds the Windows CLI with the profile
  option. There is no Windows runtime in this environment, so option behavior,
  profile round trips, and reparse-point race checks remain unqualified.
- On 2026-10-27, `make CC=gcc test` passed all unit and integration suites,
  including 265 archive-format checks, 160 CLI integration checks, the Atari
  path-projection fixture, and the Hurd/Solaris/illumos host-shim extraction
  checks. The
  archive checks include independently laid-out blocked and single-blob
  archives through both cores, and explicit rejection of versions 1–5 by full
  and mini info/test readers. The standard target also runs `check_symlink_atomic.py`,
  which tests no-follow symlink times, no-clobber behavior, staged forced
  replacement, and cleanup after a forced timestamp error. It runs host profile fixtures for
  QL, X68000, Plan 9, and the POSIX macOS CLI, plus full DOS lifecycle and
  CP/M-86 projection checks. When DJGPP is installed, it also cross-builds the
  full DOS frontend; these host checks do not qualify unavailable native
  runtimes.
- `make CC=gcc dos-host-test` passes the full DOS host lifecycle checks and
  profile create/add cases. `python3 test/check_dos_profile.py --boltpack
  build/dos-host-test/boltpack --linux-boltpack build/linux/boltpack
  --mini-boltpack build/linux32mini/bpmini` confirms profile methods and
  16 KiB blocks and integrity-checks create/append output with the DOS host
  frontend, Linux full reader, and QEMU-run Linux mini reader. The fixture also
  verifies Stored output, conflicting option refusal, and byte-preserving
  rejection of an append to an archive using an incompatible codec.
  The full run exercised profile create, append, incompatible-option refusal,
  byte-preserving refusal of an extended-codec archive, and dry-run validation
  without destination creation. It now also builds host QL, X68000, and Plan 9
  CLI fixtures and verifies their Stored/BoltLite profile archives with both
  full and mini readers. `make linux-gui`
