## Core evidence

- Full and mini cores emit and accept format 6 only.
- Both cores validate counted UTF-8 names, canonical relative path components,
  primary-name uniqueness, inline/table agreement, and supplementary-group
  framing before extraction or archive editing.
- Portable metadata envelopes are bounded to 256 bytes. Duplicate or orphaned
  portable records and duplicate resource forks are rejected.
- The mini writer and reader enforce the serialized-size limit, including file
  table and footer overhead. Host tests exercise write overflow, finalization
  overhead, and oversized header rejection.
- Three fixed format-6 archives are laid out from the normative format and
  codec descriptions without calling either archive writer: a 170-byte
  blocked Stored entry, a 158-byte unframed Stored entry, and a 159-byte
  unframed BoltLite entry. Both cores integrity-test the layouts and extract
  both single-blob cases. Checks cover matching inline/table fields, unknown
  timestamps, fixed payload/table/header CRC-32 values, corrupt payload
  detection, and mini rejection of an oversized single blob before opening
  output.
- The full writer API and Linux and Windows CLIs can opt into Interchange
  Profile 1. The Linux and Windows FLTK GUIs offer it for creation/network
  sending; the Atari GEM and native Win32 GUIs offer it for creation. The full
  writer checks method, block size, entry size/count, projected table and
  footer size, and existing archive conformance before profile append. A mini
  reader verifies a profile archive emitted by the full writer.
- `make win32-exe win64-exe` cross-builds the Windows CLI with the profile
  option. There is no Windows runtime in this environment, so option behavior,
  profile round trips, and reparse-point race checks remain unqualified.
- On 2026-10-27, `make CC=gcc test` passed all unit and integration suites,
  including 231 archive-format checks and 151 CLI integration checks. The
  archive checks include independently laid-out blocked and single-blob
  archives through both cores, and explicit rejection of versions 1–5 by full
  and mini info/test readers.
  The full run exercised profile create, append, incompatible-option refusal,
  and byte-preserving refusal of an extended-codec archive. `make linux-gui`
  also built successfully. A Linux CLI fixture with a valid portable FAT
  record returned partial while restoring the directory's Unix mode and epoch
  time.
- `ASAN_OPTIONS=detect_leaks=0 make CC=gcc unit-test-asan` passed the ASan/UBSan
  unit suites, including all 231 archive-format checks. Leak detection must be
  disabled in this container because LeakSanitizer cannot run under its ptrace
  restrictions.
- After the CP/M-86 projection checks were added, `make CC=gcc mini-test
  unit-test` passed all 241 archive-format checks, and `make CC=gcc
  cpm86-host-test` passed the CP/M-86 create/list/extract and refusal fixtures.
- `make mini-all unit-test-dos16` rebuilt the DOS16, Win16, and OS/2-16 mini
  targets; DOSBox ran the DOS16 unit fixture (20 passed, 0 failed).
  `test/check_dos16_interop.py` passed DOS16-to-Linux transfer, including nested
  paths, portable FAT metadata, and fixed-offset timestamps.
  `make linuxmini` plus `BP_TEST_LINUXMINI_RUNNER=qemu-i386
  python3 test/check_linuxmini_interop.py` passed Linux mini metadata, full/mini
  transfer, overwrite preservation, symlink refusal, and corrupt-file cleanup.
- GUI interaction was not runtime-tested: Xvfb starts but this environment
  cannot open its display. Atari, OS/2, and Windows evidence remains
  cross-build-only; target runtime checks are still outstanding.

This matrix is intentionally not a support promise for every OS listed in
`frontends.md`. Completion requires either the listed capability to be
implemented and validated or a deliberate, user-visible refusal/reporting
policy for that adapter.
